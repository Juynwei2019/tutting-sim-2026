# Tutting Pose 學習系統 — 實作規格

## 背景
這是一套互動式姿勢生成與評分系統,用於訓練/收斂出符合美感的 tutting（機械舞手臂動作）姿勢。
使用者透過反覆評分與微調，逐步調整出滿意的姿勢，系統記錄完整歷程，未來可依據累積的歷史資料自動生成 tutting combo（連續動作組合）。

## 關節定義
系統控制以下6個關節，每個關節為三軸旋轉角度 [x, y, z]：
- LeftArm / RightArm（上臂，肩到肘）
- LeftForeArm / RightForeArm（前臂，肘到腕）
- LeftHand / RightHand（手部）

每個關節、每一軸都有獨立的角度限制範圍（min, max）與格點間距（grid step，例如15度一格）。
角度限制與格點間距需要做成可配置的資料表（非寫死在程式碼中），例如：

joint_limits = {
  "LeftArm":     {"x": {"min": -90, "max": 90, "step": 15}, "y": {...}, "z": {...}},
  "RightArm":    {...},
  "LeftForeArm": {...},
  "RightForeArm":{...},
  "LeftHand":    {...},
  "RightHand":   {...},
}

## 完整流程

### 1. 產生pose
使用者點選 [產生pose] 按鈕，觸發步驟2。

### 2. 隨機產生初始對稱pose
- 對每個關節、每一軸，依據該軸的限制範圍與格點間距，隨機抽樣一個合法格點值
- 對稱規則：Left側抽樣後，Right側角度為鏡射值（LeftArm 抽到 [x,y,z] → RightArm = mirror([x,y,z])，鏡射邏輯視骨架座標系定義，通常是某軸取負值）
- 產生完整的6關節初始pose

### 3. 開始評分
- 顯示目前pose，使用者從6個關節中選擇一個「不喜歡」的關節
- 提供一個開關：「是否連動對側」（此次微調是否同步套用鏡射delta到對側關節）
  - 建議預設值：Arm/ForeArm 類關節預設開啟連動，Hand 類關節預設關閉（因手部動作常刻意不對稱）

### 4. 微調關節
- 系統對使用者選中的關節，隨機挑選一軸（X或Y或Z，允許重複挑選同一軸)
- 依該軸的格點間距，做鄰近格點微調（例如 LeftHand[x, y, z] → LeftHand[x+15, y, z]）
- 若「連動對側」開啟，同步套用鏡射delta到對側關節
- 顯示微調後的pose，使用者評價「喜歡 / 不喜歡」
- 若不喜歡，使用者可選擇「回到上一步」，退回此次微調前的角度值（僅限這一次微調，非整個session）

### 5. 連續3次不喜歡 → 略過機制
- 對同一關節維護一個「連續不喜歡計數器」（per-joint，非全域）
  - 若使用者中途對該關節評為「喜歡」，計數器歸零
  - 「回到上一步」不影響此計數器的累加（計數只看評價結果，不看是否退回）
- 當計數器達到3時觸發略過：
  a. 該關節退回到「這一連串連續微調開始前」的角度值（即第一次被評不喜歡之前的狀態，非整個session最初的隨機值）
  b. 若此關節微調過程中曾連動對側，對側關節同步一併退回對應的鏡射前狀態
  c. 記錄本次略過事件（skipped: true），計數器歸零
  d. 系統不自動指定下一個關節，返回步驟3，由使用者自行選擇下一個要評分的關節

### 6. 下一次評分
返回步驟3，重複流程。

### 7. 每10次評分提示是否結束
- 維護一個全域評分輪次計數器（不分關節，每次使用者對一次微調結果評價"喜歡/不喜歡"就+1）
- 每達到10的倍數，跳出提示「已評分10輪，是否結束此次調整？」
- 使用者可選擇「繼續評分」或「前往完成」

### 8. 使用者按下 [產生pose完成]
使用者主觀認可目前pose，觸發步驟9。

### 9. 紀錄評分歷程與最終結果
存入「學習動作結果」資料庫，需包含以下資料：

**每輪評分歷程（陣列，記錄每一次微調行為）：**
{
  "session_id": "唯一識別此次產生pose的session",
  "round": 整數，第幾輪評分,
  "joint": "被評分的關節名稱",
  "axis": "被微調的軸 (x/y/z)",
  "delta": 微調量（如 +15 或 -15）,
  "mirrored": 布林值，是否連動對側,
  "liked": 布林值，使用者評價,
  "reverted": 布林值，是否按了回到上一步,
  "skip_triggered": 布林值，此輪是否觸發略過機制,
  "pose_snapshot": {6關節的完整角度快照}
}

**最終結果：**
{
  "session_id": "...",
  "final_pose": {6關節的最終角度},
  "total_rounds": 整數,
  "skipped_joints": ["曾被略過的關節列表"],
  "timestamp": "..."
}

## 技術要求
- 角度限制與格點資料需可配置，不寫死在邏輯程式碼中
- 需要有pose的即時預覽（3D模型或示意圖，視實作平台而定）
- 需妥善處理「回到上一步」與「略過退回」兩種不同層級的retreat機制，避免搞混
- 資料寫入需具備原子性，避免中途中斷導致歷程資料不完整

## 未來延伸（本次不需實作，僅供架構預留）
- 依據「學習動作結果」的歷史資料，訓練或設計規則，自動挑選姿勢序列組成 tutting combo
- 可能需要額外記錄「姿勢之間的過渡合理性」評分，供combo生成使用

## 待確認/可能需要與需求方對齊的開放問題
1. 骨架座標系的鏡射公式（哪一軸取負值，視具體使用的3D引擎/骨架標準而定，例如Unity的T-pose座標系 vs 自定義骨架）
2. Hand關節是否需要更細的角度限制（因手腕動作範圍通常比手臂複雜）
3. 若使用者從未觸發「連續3次不喜歡」，是否仍要保留一個「使用者主動放棄此關節」的按鈕（目前流程只有系統自動判定的略過，沒有使用者主動略過的選項）
